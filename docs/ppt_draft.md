## Slide 8
### 프로젝트 개요 - 기술 스택 및 아키텍처 설계
 - 기술 스택
   - 언어/런타임: Python 3.10+, UV 패키지 관리자
   - 라이브러리: LangChain(Core/Community), FAISS, PyMuPDF, RAGAS, Streamlit, SQLite, python-dotenv

   - 운영: GitHub, Slack
 - 아키텍처 요약
   - PDF→텍스트 분할(RecursiveCharacterTextSplitter)→임베딩(Upstage embedding-query)→FAISS 저장/검색
   - QueryRouter로 제빵 관련 여부 판단, RAG 경로/일반 LLM 경로 분기
   - RAG 프롬프트(제빵 전문가 페르소나) + Upstage Chat(solar-pro2 등)
   - Streamlit WebUI, RAGAS 기반 품질 평가


## Slide 10
### 프로젝트 수행 절차 및 방법 - 작품 소개
 - 프로젝트명: 제과제빵 문서 기반 RAG 시스템
 - 배경: 제빵 지식은 공정/온도/위생 등 세부 근거가 중요하나 자료 접근성이 낮음
 - 목적: 신뢰 가능한 출처 기반의 정확한 답변 제공 및 학습 효율 향상
 - 목표: 빠른 검색·정확한 생성·근거 제시·운영 자동화(증분 인덱싱/로그/평가)


## Slide 11
### 프로젝트 수행 절차 및 방법 - 구현 전략
 - 시스템 구조: 모듈화(`VectorStoreManager`, `LLMManager`, `RetrieverManager`, `RAGQueryProcessor`, `QueryRouter`)
 - 프롬프트 전략: 제빵 전문가 페르소나, 근거 우선, 출처 페이지/파일 표기
 - 데이터 처리: PDF 로더 최적화, 파일명/상위폴더명을 청크 앞에 주입하여 검색성 강화
 - 검색: Upstage 임베딩 + FAISS, k 선택 및 스코어 튜닝, 증분 인덱싱
 - 라우팅: 제빵 관련 질의만 RAG 적용, 일반 지식은 LLM 직접 응답
 - 평가: RAGAS 4지표(faithfulness 등) 자동 측정 및 JSON 저장
 - UI/운영: Streamlit WebUI, SQLite 대화저장, UV로 재현 가능한 실행


## Slide 12
### 프로젝트 수행 절차 및 방법 - 기능 리뷰
 - 기능1: 프롬프트 엔지니어링
   - 제빵 전문가 페르소나, 근거 중심 답변, 출처 표기 규칙

   - QueryRouter로 제빵/일반지식 분리, 리소스 효율화
 - 기능4: 증분 인덱싱/파일 변경 감지
   - 수정/신규만 업데이트, 삭제 처리 재구성 옵션, 메타데이터 관리
 - 기능5: WebUI 및 대화 히스토리
   - Streamlit 인터페이스, SQLite 저장, 컨텍스트 활용
 - 기능6: 평가 자동화
   - RAGAS 4지표 측정, 결과 JSON 저장·비교


## Slide 13
### 프로젝트 수행 절차 및 방법 - 트러블 슈팅
 - 문제 1: Gemini API rate limit 발생
   - 해결: LLM 호출 10초 간격, 임베딩은 10개 문서 단위로 10초 간격 처리
 - 문제 2: 파일명이 중요한데 문서 내용으로만 검색됨
   - 해결: 각 청크 앞에 "상위폴더명/파일명"을 주입하여 임베딩·저장
 - 문제 3: 모든 질문을 RAG로만 처리되어 불필요한 검색 비용
   - 해결: 라우터로 일반 답변/제빵 RAG 분기 처리
 - 문제 4: 기동 시 벡터스토어 생성에 30초+ 소요
   - 해결: FAISS 디스크 영구화/로드, 파일 변경 감지, 증분 업데이트, 삭제 재구성, 메타데이터 관리
